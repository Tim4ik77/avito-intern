# Поиск объявлений Авито

Моё лучшее отправленное решение: **Recall@50 = 0.920251**, локально — **0.960115**.

## Как проверить

Нужен Python 3.12. Положите **исходные файлы конкурса** в папку `dataset/` рядом с `predict.py`:

```text
avito-solution/
├── dataset/
│   ├── train.parquet
│   ├── benchmark_items.parquet
│   └── benchmark_queries.parquet
├── bundle/
├── predict.py
└── ...
```

Данные не входят в Git и исключены через `.gitignore`. Названия и содержимое файлов должны совпадать с оригиналами конкурса.

```bash
python -m pip install -r requirements.txt
python predict.py
python experiments.py
```

Если данные уже лежат в другом месте: `python predict.py --data-dir ../dataset`.
Скрипт предсказания создаёт `answer.csv`: 2452 запроса, по 50 объявлений. Четыре модели заново считают баллы на CPU; GPU и сеть после установки зависимостей не нужны. Скрипт проверяет SHA-256 исходных данных, артефактов и **побайтовое совпадение ответа с отправленным файлом**.

В репозитории сохранены веса и рассчитанные признаки кандидатов. Это воспроизведение отправки из готовых артефактов; подготовка признаков с нуля здесь не запускается. `experiments.py` пересчитывает метрики по сохранённым OOF-предсказаниям и работает без Parquet. GitHub Actions проверяет код, хеши артефактов и эти метрики; полный запуск `predict.py` проверяется локально с данными.

## Данные и подход

Я использовал пары запрос–выбранное объявление из `train.parquet`, запросы и объявления benchmark. Текст запроса, заголовок, описание и параметры помогают определить услугу; локация и расстояние — её доступность. Категория, цена, рейтинг, отзывы и фильтры дают дополнительные сигналы. ID нужны для связывания таблиц и формирования ответа.

Кандидатов собирал лексическим поиском (BM25, символьный TF-IDF) и семантическим поиском: исходные и дообученные **Multilingual E5 Small/Base**, фрагменты описаний и прототипы похожих запросов из истории. Затем применял ансамбль **двух LightGBM и двух CatBoost** с 71–83 признаками: сходство текстов, география, категории, статистики истории и ранги поисковых каналов. Формула объединения находится в `solution.py`, полный список признаков — в `bundle/manifest.json`.

## Основные эксперименты

| Вариант | Локальный Recall@50 |
|---|---:|
| LightGBM + CatBoost, 71 признак | 0.951063 |
| Расширенные кандидаты и прототипы | 0.957136 |
| Дообученный E5 Base и итоговый ансамбль | **0.960115** |

Проверял на 8000 запросах: четыре фолда по нормализованному тексту, каждый раз 6000 запросов для обучения ранжировщиков и 2000 для проверки. Все 8000 текстов исключил из истории для дообучения E5 и вспомогательных статистик. Recall считал по полной разметке: 8493 положительных пары, включая объявления, потерянные при поиске кандидатов.

Модели и параметры выбирал по этой OOF-валидации, поэтому она не является независимым финальным тестом. Итог на платформе ниже: **0.920251**.

## Какие ошибки исправлял

- Нужное объявление не попадало в кандидаты — добавил E5 Base, фрагменты описаний и прототипы. Полнота локального пула выросла с 0.98035 до 0.98917.
- Короткие запросы и разные названия одной услуги — добавил семантические признаки и дообучение на истории.
- Подходящая услуга в другом городе — использовал географию и вероятность удалённой услуги.

Для точного повтора сохранил особенность отправленной версии: ASCII-нормализация заголовка в группировке с локацией удаляет кириллицу. Изменение этого правила меняет ответ.

## Файлы

- `predict.py`, `solution.py` — предсказание и проверка ответа.
- `experiments.py`, `validation.npz`, `report.json` — три эксперимента, разметка, метрики и параметры обучения.
- `train.py`, `features.py` — ключевой код дообучения E5 и обучения ранжировщиков. Для его запуска нужны подготовленные промежуточные файлы исследования в `artifacts/` и исходные веса E5 в `models/`; они не входят в поставку. Это дополнительный код для разбора подхода, не обязательный шаг проверки. Зависимости — `requirements-training.txt`, параметры запуска — `python train.py --help`.
- `bundle/` — четыре модели, признаки в 20 частях и порядок ID. Все эти файлы нужны для точного воспроизведения и входят в Git.

Для публикации достаточно отправить ветку `main` в GitHub. Parquet добавлять не нужно.
